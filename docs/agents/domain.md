# Domain documentation

This project uses one domain context. Its glossary is `GLOSSARY.md` at the repository root. Architecture decision records (ADRs) live in `docs/adr/`.

Before exploring a topic, read the glossary and any ADRs that apply. If a file does not exist, continue without it. Create domain documentation when the domain-modeling workflow calls for it.

Use the glossary's terms in issues, proposals, hypotheses, and tests. If a term is missing, consider whether the domain model needs it. If a proposal conflicts with an ADR, name the conflict and explain whether the decision needs review.

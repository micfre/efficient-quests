# Domain documentation

This project has one domain context. Its glossary is `GLOSSARY.md` at the repository root. Architecture decision records (ADRs) are in `docs/adr/`. An ADR records one design decision and the reason for it.

Before you explore a topic, read the glossary and the ADRs that apply. If a file does not exist, continue without it. Create domain documentation when the domain-modeling workflow requires it.

Use the terms of the glossary in issues, proposals, hypotheses, and tests. If a term is missing from the glossary, decide whether the domain model needs it. If a proposal conflicts with an ADR, name the conflict. Then state whether the decision needs a review.

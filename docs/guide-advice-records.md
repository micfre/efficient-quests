# Guide advice records

`EfficientQuests.ExtractGuide(packageName, context)` interprets the registered chapters of one package and returns candidate advice in source order. It is an input to relevance, lifecycle, and presentation processing; a candidate is not a verified gameplay fact or automatically a visible hint.

Each record contains a stable source `id`, `package`, `sourceAuthor`, `chapter`, selected `sourceText`, shortened `text`, `sourceOrder`, and optional `kind` (`supply`, `flight`, or `technique`). An item `itemID` and `quantity` are supplied only when present in an item tag; an item tag does not establish a retention requirement or independent consumption.

`itemSourceName` is the optional item label written in that same tag. It is guide text, not provider-verified metadata. TUG's shopping list contains inconsistent IDs and names (for example, its page 10 entry reuses page 1's ID), so downstream code must not assume the tag's ID and label identify the same item. Verify them against available provider facts before linking or combining requirements; if that cannot be done, retain the uncertainty.

`association` is `zone`, `quest`, or `quests`. A single explicit quest reference has `questID` and a one-element `questIDs` list. Multiple quest references have `questIDs` and no `questID`; `uncertain` remains true because the prose does not prove which part applies to each quest. No quest reference produces an empty list and does not invent an association. Visible text resolves a preposition-introduced run of quest tags to "for this quest" or "for these quests", keeping surrounding punctuation, so tag removal cannot leave dangling wording; an ordinary use of the same preposition is preserved verbatim.

`inferredQuestIDs`, when present, records a possible relationship between a standalone technique and quest references in its following source sentence. These IDs are not confirmed associations: the record remains a zone tip, carries no `questID`, and is marked uncertain. Consumers must not present this inference as a guide or provider fact.

`location`, when present, has `x`, `y`, `zone`, `coordinateSystem = "guide-percent"`, `zoneSource = "guide-name"`, and an `inherited` flag. Its named zone and 0–100 coordinates must not be compared directly to a numeric client map ID or 0–1 position without a reliable mapping. `conditions` lists unsupported or unobserved restrictions and `uncertain` identifies candidates needing qualification.

Tags placed before a step's prose are position markers. Their coordinate zone and bare item counts do not appear in `text`, while an item tag still supplies `itemID` and `quantity`. A named flight point tag identifies travel advice: `text` names the point when its own prose does not. A bare objective directive carrying exactly one identified item quantity becomes `supply` advice stating that requirement, marked uncertain with a `requirement from an objective directive` condition; directives without that shape stay withheld. Retention wording must take an object, so a fortress name in prose or a point name in a tag cannot satisfy it.

`learningState` contains any guide learning markers as `{kind, id or name, rank, suffix, known}`. `known` is present only when supported by a positive or negative observation. Such a marker describes the guide step's learning target; it does not prove that a linked quest is complete. The context can provide `isSpellKnown(id)` and `skillRanks` for observations. Unavailable observations remain unknown.

Extraction deliberately withholds some ambiguous prose. Its narrative screening is heuristic and does not prove that arbitrary source material is spoiler-free. Expand coverage using reviewed examples and tests, and retain uncertainty when an association, condition, or location cannot be resolved. `tools/audit_extraction.lua` runs this extraction over installed packages and reports safety findings and withheld candidates; `docs/tug-extraction-audit.md` records the reviewed corpus results and the known withheld categories.
